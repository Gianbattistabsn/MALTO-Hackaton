## Overview

This project was developed for the **Malto Recruitment Hackathon** on Kaggle. The challenge addresses a multi-class text classification problem where the goal is to identify which AI model (or human) generated a given piece of text.

**Kaggle Competition**: 👉 [Malto Recruitment Hackathon](https://www.kaggle.com/competitions/malto-recruitment-hackathon/)

### Dataset Overview
The dataset contains 6 classes with varying distributions, making it an imbalanced classification problem:
- **Classes**: Human (0), DeepSeek (1), Grok (2), Claude (3), Gemini (4), ChatGPT (5)
- **Challenge**: Distinguishing between subtle writing styles of different AI models

### Key Challenges
- **Class Imbalance**: Different AI models appear with different frequencies in the dataset
- **Subtle Distinctions**: Different AI models often produce texts with similar statistical properties (and topics).
- **High Dimensionality**: Raw text data generates thousands of features that don't help with classification

### Solution Strategy
I've implemented a complete ML pipeline that combines:
1. **Advanced Feature Engineering** using ImpCHI (Improved Chi-Squared feature selection)
2. **Bayesian Hyperparameter Optimization** using Optuna
3. **Ensemble Methods** combining multiple LightGBM models
4. **Probability Calibration** for reliable prediction confidence
5. **Model Stacking** to learn optimal model combination weights

## Data Strategy

### Train-Test Split (Internal Validation)

To develop and evaluate the pipeline, I created an internal validation set from the Kaggle training data:

- **Internal Training Set**: 75% of the provided training data
- **Internal Validation Set**: 25% of the provided training data
- **Stratification**: Both sets maintain the original class distribution (essential for imbalanced data)
- **Purpose**: Develop and tune the model without touching the official test set until final submission

This stratified split ensures:
- Each fold maintains class proportions
- Validation metrics are reliable and representative
- Hyperparameter selection is unbiased
- No data leakage occurs during model development

The final submission uses a model trained on **all available training data** to maximize performance on the official Kaggle test set.

## Technical Approach

### 1. Feature Engineering with ImpCHI

I employ **ImpCHI (Improved Chi-Squared)** feature selection, a specialized algorithm designed for imbalanced text classification datasets. Here's why this is critical:

#### The Problem
Raw text data using TF-IDF or bag-of-words creates:
- **10,000+ features** from a modest corpus
- High sparsity (most samples have zero values for most features)
- Curse of dimensionality leading to overfitting
- Computational inefficiency

#### The ImpCHI Solution
Chi-Squared feature selection measures the statistical dependence between features and class labels. ImpCHI improves on standard Chi-Squared by:

- **Per-Label Selection**: Selects k features for *each* class independently
  - Prevents majority classes from dominating feature selection
  - Ensures minority classes have discriminative features
- **N-gram Support**: Captures phrase-level patterns (unigrams, bigrams, trigrams)
  - "AI generated" vs "AI-generated" captures subtle variations
  - Trigrams capture longer contextual patterns
- **Document Frequency Thresholding**: Filters ultra-rare features (min_df)
  - Removes noise while preserving signal
  - Reduces computational cost

**Configuration in This Project**:
```python
Chi2TextFeatureSelector(
    k_per_label=45,      # 45 features per class = ~270 features total
    min_df=3,            # Feature must appear in ≥3 documents
    ngram_range=(1, 3)   # Unigrams, bigrams, trigrams
)
```

**Source**: The ImpCHI algorithm is based on my previous project:
👉 [Winter Project DSMLL 2025-2026](https://github.com/Gianbattistabsn/Winter-project-DSMLL-2025-2026-ImpChi-and-W2V)

### 2. Model Selection: LightGBM

I chose **LightGBM (Light Gradient Boosting Machine)** as the base learner for several reasons:

#### Advantages Over Alternatives
| Aspect | LightGBM | Standard GBDT | Random Forest | SVM |
|--------|----------|---------------|---------------|-----|
| **Speed** | Fast (leaf-wise growth) | Slower (level-wise) | Medium | Slow |
| **Memory** | Low (leaf-wise) | Higher | Higher | High with kernels |
| **Imbalance Handling** | `class_weight='balanced'` | Manual tweaking | Weak | Requires custom weighting |
| **Feature Importance** | Excellent | Good | Good | Limited |
| **Scalability** | Excellent | Good | Medium | Poor |

### 3. Hyperparameter Optimization: Optuna + Stratified CV

I performed extensive hyperparameter tuning using:
- **Algorithm**: Optuna (Bayesian Optimization)
- **Strategy**: Stratified 5-Fold Cross-Validation
- **Budget**: 50 trials

#### Why Bayesian Optimization?
Unlike grid search or random search that exhaustively or randomly sample the hyperparameter space, Bayesian optimization intelligently explores by:
1. Training a model with sampled hyperparameters
2. Observing the validation score
3. **Learning a probability model** of the objective function
4. Proposing hyperparameters expected to improve performance
5. Repeating the process

**Efficiency Gain**: Finds good solutions with far fewer evaluations than grid search.

#### Why Stratified 5-Fold CV?
- **Stratification**: Each fold maintains the original class distribution
  - Critical for imbalanced data
  - Prevents one fold from having zero samples of a rare class
- **5-Fold**: Standard choice balancing bias-variance and computational cost
  - 5 splits = independent validation estimates
  - Average of 5 folds more reliable than single train-val split

#### Tuned Hyperparameters
```python
# Hyperparameters explored during optimization
- n_estimators: [100-1000] boosting rounds
- learning_rate: [0.001-0.1] step size
- max_depth: [3-15] tree complexity
- num_leaves: [20-300] leaf count
- min_child_samples: [10-100] min samples per leaf
- reg_alpha, reg_lambda: [0.0-1.0] L1/L2 regularization
- colsample_bytree, subsample: [0.2-1.0] feature/sample subsampling
```

### 4. Model Selection and Ensemble

After 50 trials, I selected the **two best configurations**:

**Model 31** (Conservative Approach):
- Lower learning rate (0.010) → slower but steadier learning
- Shallow trees (max_depth=5) → reduced overfitting risk
- More boosting rounds (730) → compensates for slower learning
- **Strength**: Better generalization to unseen data

**Model 8** (Complex Approach):
- Moderate learning rate (0.005) → balanced learning
- Deeper trees (max_depth=8) → captures complex patterns
- More boosting rounds (922) → extensive learning
- **Strength**: Better captures subtle patterns in training data

**Why Two Models?**
Diversity is the foundation of ensemble learning. These models have:
- Different regularization strategies
- Different tree depths (explore different complexity levels)
- Different feature emphasis (via different learning paths)

Using both captures the **bias-variance tradeoff**:
- Model 31 reduces variance (overfitting)
- Model 8 reduces bias (underfitting)

### 5. Model Calibration with Isotonic Regression

Before ensembling, I calibrate each base model using **Isotonic Regression**:

#### What is Calibration?
Calibration ensures predicted probabilities match actual likelihoods:
- **Uncalibrated**: Model predicts 0.8 probability, but actual rate is 0.5
- **Calibrated**: Model predicts 0.5, actual rate ≈ 0.5

#### Why Calibrate Base Models?
- **Ensemble Quality**: Better base model predictions → better ensemble predictions
- **Confidence Reliability**: When model predicts 0.9, it should be ~90% correct
- **Down-stream Applications**: Calibrated probabilities useful for decision thresholds

#### Isotonic Regression vs. Platt Scaling
| Method | Parametric | Flexibility |
|--------|-----------|-------------|
| **Isotonic** | No | Very flexible |
| **Platt** | Yes (sigmoid) | Less flexible |

I chose isotonic because it can handle diverse miscalibration patterns without assuming a specific functional form.

**Implementation**:
```python
CalibratedClassifierCV(
    LGBMClassifier(**params),
    method='isotonic',  # Non-parametric calibration
    cv=5  # Prevents data leakage using cross-validated calibration
)
```

### 6. Stacking: Learning Optimal Ensemble Weights

Rather than averaging predictions equally, I use **stacking** to learn which base model to trust when:

#### Architecture
```
Base Model 1 (Calibrated) ──┐
                            ├──> Meta-learner (LogisticRegression) ──> Final Prediction
Base Model 2 (Calibrated) ──┘
```

#### Meta-learner Details
- **Algorithm**: Logistic Regression (simple, interpretable, fast)
- **Input Features**: Probability outputs from base models (6-dimensional per sample)
- **Output**: Final class probability
- **Regularization**: C=0.1 (strong regularization prevents meta-model overfitting)
- **Class Weighting**: `balanced` to handle any residual imbalance in meta-features
- **Cross-Validation**: 5-fold during stacking prevents data leakage

#### Implementation Benefits
1. **Learns Optimal Weights**: Meta-learner discovers when Model 31 vs Model 8 is more reliable
2. **Exploits Diversity**: Captures complementary strengths of both models
3. **Simple and Interpretable**: Logistic Regression coefficients show which model is trusted more
4. **Efficient**: Meta-learner trained on only (n_samples, 6) data

  ↓
[Feature Extraction] → TF-IDF features
  ↓

  ↓
[Standardization] → Zero mean, unit variance
  ↓

- **Macro F1**: Average F1 across all classes (fair for imbalanced data)
